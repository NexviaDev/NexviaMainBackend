[나라장터 입찰공고 백엔드 계획 요약]

0) 실행
- backend 디렉터리에서 npm start → nodemon app.js (진입 파일: app.js)
- 개발 기본 포트는 5001입니다. 프론트엔드는 http://localhost:3001 에서 실행하고, API는 http://localhost:5001 을 호출합니다.

1) 역할
- 공공데이터포털 조달청 입찰공고정보·낙찰(개찰) OpenAPI(apis.data.go.kr)를 호출하는 프록시입니다.
- 기업마당 지원사업정보(bizinfoApi.do)는 GET /api/v1/bizinfo/support 로, 행사·교육(bizinfoEventApi.do)은 GET /api/v1/bizinfo/events 로 프록시하며 crtfcKey 는 서버의 BIZINFO_CRTFC_KEY 로만 붙입니다.
- 나라장터 사전규격·발주계획은 각각 GET /api/v1/prespec/:operation, GET /api/v1/ordrplan/:operation — 오퍼레이션은 사전규격 getPublicPrcure*/getInsttAccto*/getThngDetailMeta*, 발주계획 getOrderPlanSttus* 를 허용, ServiceKey 는 서버가 붙입니다(PRESPEC_BASE_URL, ORDR_PLAN_BASE_URL, 포털에서 해당 서비스 활용신청 필요).
- 중소벤처기업부 RSS(사업공고·공지)는 GET /api/v1/feeds/mss?smba_board=310|81 — 서버 메모리 캐시 약 5분.
- 인증키(ServiceKey·crtfcKey)는 backend/.env 에만 보관하고 브라우저로 내려보내지 않습니다.

2) 호출 규약
- 입찰공고: GET /api/v1/bid/:operation?... — :operation 은 getBidPblanc 로 시작하는 이름만 허용.
- 낙찰·개찰(예비가·순위 등): GET /api/v1/openg/:operation?... — :operation 은 getOpengResult 로 시작하는 이름만 허용.
- 기업마당 지원사업: GET /api/v1/bizinfo/support?dataType=json&pageUnit=15&pageIndex=1&hashtags=... — 허용 쿼리만 upstream 에 전달, crtfcKey 는 서버 고정.
- 기업마당 행사: GET /api/v1/bizinfo/events?... — 동일하게 허용 쿼리만 전달, crtfcKey 서버 고정.
- 사전규격: GET /api/v1/prespec/:operation?... — getPublicPrcure/getInsttAccto/getThngDetailMeta 로 시작하는 이름만 허용, 나머지 쿼리는 upstream 으로(인증키는 PRESPEC_AUTH_QUERY 로 ServiceKey | serviceKey | both 중 선택, 기본 ServiceKey).
- 발주계획: GET /api/v1/ordrplan/:operation?... — getOrderPlanSttus 로 시작하는 이름을 사용합니다. 기본 End Point 는 https://apis.data.go.kr/1230000/ao/OrderPlanSttusService 이며 ORDR_PLAN_AUTH_QUERY 동일.
- RSS: GET /api/v1/feeds/mss?smba_board=310 또는 81.
- 입찰공고 upstream 기본 URL은 BID_PUBLIC_INFO_BASE_URL, 개찰·낙찰 upstream 은 OPENG_RESULT_BASE_URL 입니다. (낙찰정보 1.1 기본값: …/as/ScsbidInfoService)
- 서버가 DATA_GO_KR_SERVICE_KEY 를 합쳐 upstream 으로 전달합니다.

3) 슬립·지연 대응
- axios timeout 은 60초, 네트워크/5xx 시 최대 2회 재시도(간단 지수 백오프).

4) 확장
- 참고문서에만 있고 UI에 없는 선택 파라미터는 동일하게 쿼리로 넘기면 upstream 까지 전달됩니다(단, serviceKey 는 서버 값으로 덮어씀).

5) 보조 데이터 소스(RSS·타 기관 API)
- 나라장터 이외 RSS·공공 API 후보는 루트의 supplementary_data_sources.json 에 정리해 두었습니다.
- RSS·기업마당 등은 별도 인증키·이용조건이 있으므로, 수집 배치나 별도 라우트를 추가할 때만 서버에 키를 두고 호출하는 것을 권장합니다(프론트 직접 호출 지양).

6) 식물 AI 식별 (Gemini Vision)
- POST /api/v1/plants/identify — JSON body: { imageBase64, mimeType } (JPEG/PNG/WebP/GIF, 약 4MB 이하 권장).
- 응답 result.referenceImages: 1순위 추정 종의 Wikipedia 참고 사진 최대 6장.
- 응답 result.similarCandidates: 비슷한 종 2~4개 + referenceImages(최대 2장), imageUrl(대표 1장).
- GEMINI_API_KEY 는 backend/.env 에만 보관. 브라우저로 키를 내리지 않음.
- GEMINI_MODEL 기본 gemini-2.5-flash. thinkingBudget 0(속도). identify 전 warmupGemini 캐시(4분).
- axios timeout 65초, 429/5xx 시 최대 2회 재시도.
- 분당 15회 rate limit (/identify). express.json limit 6mb(이미지 base64).
- GET /api/v1/plants/health — gemini 키 설정 여부 확인.
- GET /api/v1/plants/warmup — Gemini 연결 워밍(슬립·콜드스타트 완화). 프론트 /plants 에서 20초마다 /health + /plants/health ping 권장.

7) 문서 메일머지 (DOCX)
- GET /api/v1/doc-merge/health — merge 엔진·LibreOffice 설치 여부.
- POST /api/v1/doc-merge/analyze — multipart file(.docx) → 양식 내 {{필드명}}·MERGEFIELD 목록 JSON.
- POST /api/v1/doc-merge/run — JSON { templateBase64, rows:[{...}], exportPdf? } 단일 행 DOCX/PDF.
- POST /api/v1/doc-merge/run-batch — 여러 행 ZIP (exportPdf 시 서버에 LibreOffice 필요).
- 치환 문법: Word 양식에 {{회사명}} 형태. 서버는 docxtemplater 로 치환.
- PDF: LIBREOFFICE_PATH(또는 SOFFICE_PATH) 에 soffice 가 있을 때만 --convert-to pdf. Vercel 기본은 DOCX만.
- 프론트 /merge — 양식은 브라우저 IndexedDB 저장, 생성 시 templateBase64+rows 를 API 로 전송.
- express.json limit 16mb(대용량 base64). analyze 는 multer 12mb.

8) 회원·로그인 (MongoDB)
- userId = 이메일 형식 (동일 주소로 OTP·로그인)
- POST /api/v1/auth/register/pre-verify { userId } — 중복 확인 + 이메일 OTP 발송 (1단계)
- POST /api/v1/auth/register — { userId, code, password, ... } 가입 완료 (2단계·한 화면)
- POST /api/v1/auth/login { userId, password } — 비밀번호 확인 후 이메일 OTP 발송 (1단계)
- POST /api/v1/auth/verify { userId, code } — OTP 확인 후 JWT (2단계, 유효 90일)
- POST /api/v1/auth/send-code — login 과 동일 (비밀번호 필수)
- GET /api/v1/auth/me — Bearer JWT 세션 확인
- 비밀번호 규칙: 6자 이상, 대·소문자·숫자·특수문자 포함
- env: MONGODB_URI, MONGODB_DB, AUTH_JWT_SECRET, EMAIL_USER, EMAIL_PASS, AUTH_DEV_EXPOSE_CODE(선택)
- 프론트: /login, /register (login.js, register.js)
